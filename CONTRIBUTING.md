# Contributing to CMDBuild

Thank you for your interest in CMDBuild. Please read the
[Code of Conduct](CODE_OF_CONDUCT.md) before participating.

## How the repository works

The code is developed in the maintainer's own infrastructure. This GitHub
repository receives a **snapshot of each release**, with one commit per
release. For this reason:

* the commit history here is not the full development history;
* pull requests are **not merged on GitHub**. A maintainer reviews the change,
  integrates it in the internal repository (keeping your authorship) and
  closes the pull request with a comment. The change appears in the next
  published snapshot.

## Reporting problems and proposing features

* Search the existing issues first.
* Write issues and pull requests in English.
* For bugs, use the bug report template and include the application version.
  A bug report file generated by the application is the most useful
  information you can attach.
* For vulnerabilities, do **not** open an issue: follow [SECURITY.md](SECURITY.md).

## Sending a pull request

1. Fork the repository and create a branch from `main`.
2. Keep the change focused: one problem or feature per pull request.
3. Make sure the project builds (see below) and that the tests related to
   your change pass.
4. Sign off every commit (`git commit -s`) to certify the
   [Developer Certificate of Origin](https://developercertificate.org/).
   Pull requests with unsigned commits cannot be accepted.
5. Describe in the pull request what the change does and why.

## Building

Requirements:

* JDK 25 and Maven 3.9+
* [Sencha Cmd](https://www.sencha.com/products/sencha-cmd/) 7.6.0.87, needed
  only to build the `ui` module (the Ext JS GPL SDK is downloaded automatically)
* PostgreSQL, needed only to run integration tests

Build the application:

```sh
mvn clean install -DskipTests -am -pl cmdbuild
```

Build only the Java backend modules, without the `ui` module:

```sh
mvn -B clean package -DskipTests -pl '!ui,!cmdbuild'
```

## Code style

Follow the style of the surrounding code. Keep the license header present in
the existing source files.
